# blontix — مستندات توثيق الطلبات

منصة لإنشاء مستند طلب PDF ثابت، وحفظ نسخه المستقلة في Cloudflare R2 الخاص وبياناتها في Neon PostgreSQL الخارجي. يعمل Backend على Render المجاني والواجهة على Vercel. صفحة `/verify/{secureToken}` عامة، بينما الإدارة تتطلب جلسة دخول من مرحلتين.

## التشغيل والنشر

تستخدم Production حصريًا Neon PostgreSQL وR2، دون Render Database أو Disk أو Cloudflare Worker. إعداد Render محفوظ في render.yaml بالخطة المجانية، وإعداد الواجهة في DEPLOYMENT-VERCEL.md. لا توجد قاعدة بديلة في الذاكرة أو SQLite أو LocalStorage. الاتصال أو الإعداد الناقص يمنع تشغيل الخادم. إعداد الخدمة والمتغيرات والترحيلات في [DEPLOYMENT-RENDER.md](./DEPLOYMENT-RENDER.md)، وأسماء المتغيرات دون قيم في [.env.example](./.env.example).

استخدم Node.js 22.x، ثم `npm ci` و`npm run build` و`npm start`. يطبق التشغيل ترحيلات `drizzle-postgres` تلقائيًا تحت قفل PostgreSQL؛ يمكن أيضًا تشغيل `npm run db:migrate`. مجلد `drizzle` القديم سجل لترحيلات SQLite السابقة وليس مصدر Production الحالي. ترحيل بيانات الاستضافات السابقة يحتاج عملية استيراد منفصلة تحفظ الملفات والبصمات.

## الدخول والحماية

يتحقق الخادم من `DOCUMENTS_ACCESS_PASSWORD_HASH` باستخدام Argon2id. لا يخزن كلمة الدخول الأصلية. تظهر المرحلة الأولى باسم «رمز تفعيل اللوحة»، ثم يتحقق البريد الإداري دون كشفه في الواجهة. تطابق البريد ليس إثبات ملكية لصندوق البريد ولا عامل تحقق مستقلًا.

الجلسات مربوطة بمعرف متصفح صادر من الخادم وتستخدم Cookie بخصائص `HttpOnly; Secure; SameSite=Strict` لمدة 12 ساعة. ثلاث محاولات خاطئة مجتمعة في الرمز والبريد تحظر معرف المتصفح في PostgreSQL، مع قفل بصمة عنوان الاتصال ساعة. لا توفر المتصفحات معرف جهاز ماديًا موثوقًا؛ حذف ملفات الارتباط أو تغيير المتصفح قد يتجاوز هذا النوع من الحظر.

المفاتيح الثلاثة مستقلة: `SESSION_SECRET` لحماية الدخول والجلسات، و`DATA_ENCRYPTION_KEY` لتشفير الهاتف وSnapshot ورمز التحقق المخزن ومدخلات الرندر باستخدام AES-256-GCM مع nonce عشوائي، و`AUDIT_HMAC_KEY` لسلسلة أحداث HMAC-SHA256 ذات ترتيب وبصمة سابقة ورأس وعدد أحداث محفوظين للتحقق من العبث.

## المستندات

لكل إصدار مرجع `bl-ORD-` وSnapshot وبصمة SHA-256 وMaster PDF وأصول مستقلة. يرفض PostgreSQL تعديل محتوى الإصدار المعتمد أو حذفه. التصحيح ينشئ إصدارًا جديدًا، والإلغاء يغير حالة التحقق دون حذف النسخة الأصلية. شرط R2 يمنع استبدال الملفات؛ التحميل يجلب نفس Master ويتحقق من بصمته بدل توليده مجددًا.

QR يحتوي رمزًا عشوائيًا من 32 بايت. البحث في قاعدة البيانات يستخدم SHA-256 للرمز. صفحة التحقق لا تعرض الاسم أو الجوال؛ الجوال الكامل موجود في PDF وSnapshot الإداري. الشعار والخطوط مضمّنة في حزمة الخادم ولا تحمل من عنوان الموقع. تصميم PDF والعلامة المائية محفوظان. دعم خدمة التوقيع المدار موجود في `lib/signing.ts` ولم يفعّل توقيعًا تشفيريًا دون إعداد الخدمة.

## التحقق

`/api/health` يفحص اتصال قاعدة البيانات وحاوية R2 ويعرض الحالة فقط. `tests/production-workflow.mjs` يختبر PostgreSQL حقيقيًا في schemas جديدة مع S3 محلي مخصص للاختبارات عبر AWS SDK الفعلي؛ يفحص الدخول والحظر والترحيلات والحفظ المشفر وV1/V2 والتحميل والعبث وبقاء المستند بعد إعادة التشغيل. هذا الاختبار لا يثبت اتصال R2 الخاص بالإنتاج. يتطلب Node 24 لأدوات الاختبار وصلاحية إنشاء schema في قاعدة اختبار.

`scripts/qa-pdf-visual.mjs` يفحص PDF الاختبار بصريًا بواسطة Poppler وSharp. جميع نواتج الاختبار داخل `tmp` المستبعد من Git. لا تستخدم أسرار Production لإجراء الاختبارات الآلية المحلية.
